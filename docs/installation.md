# Установка и общая настройка

## Текущая готовность

Это предварительная реализация 0.3.0 для Home Assistant 2026.10.4 и Python 3.14. Автоматические проверки используют искусственные ответы. Вход в действующий облачный аккаунт и чтение устройства подтверждены; выполнение команд настоящей печью не проверялось.

Настройка поддерживает ручной вход по почте и коду из письма. Почта и код вводятся в HA; при CAPTCHA нужен разовый помощник для Mac. В качестве дополнительного способа сохранён ввод легитимного токена.

Пользователь успешно получил письмо, ввёл код и создал общую запись в HA. Контрольное чтение состояния вернуло HTTP 200; управление осталось выключенным. При запросе CAPTCHA откройте [помощник для Mac](../tools/sangens-setup/README.md), сами нажмите «Пройти проверку», скопируйте результат и вставьте его в появившееся поле HA. Прохождение настоящего сервиса подтверждено владельцем; при изменении требований сервиса может потребоваться дополнительная проверка совместимости.

Между письмами выдерживается минимум 60 секунд. После трёх неверных кодов или двух неудачных отправок с CAPTCHA действует пауза минимум 5 минут. Явный запрос CAPTCHA открывает дополнительный шаг, без автоматической отправки. При HTTP 429 учитывается более длинный Retry-After. Запросы не повторяются автоматически, параллельные нажатия не создают очередь. После успешного входа ошибка загрузки печей не вызывает повторную авторизацию.

## Подготовка и установка после проверки входа

1. Создайте резервную копию HA. Сохраните существующий каталог `/config/custom_components/sangens`, если он есть, и конфигурацию панели. Старые записи `sangens_station` не удаляйте автоматически.
2. Распакуйте архив интеграции так, чтобы файлы оказались в `/config/custom_components/sangens/`. Не копируйте окружение разработки, APK, тесты или токены в общедоступный `/config/www/`.
3. Перезапустите HA в удобное время. Откройте «Настройки → Устройства и службы → Добавить интеграцию → Печь Sangens».
4. Администратор выбирает «Вход по почте и коду», сам вводит почту существующего аккаунта и код из письма, затем выбирает печь. По умолчанию разрешено только чтение. Все пользователи HA получают те же сущности, повторно настраивать Sangens на телефонах не нужно.
5. Сравните температуру воздуха, камней, режим и состояние с официальным приложением. Несовпадение показаний не исправляется отправкой команд.
6. Подключите общий ресурс и карточку по `docs/card.md`. Сохраните настройки панели один раз для всех пользователей. При желании разместите личную копию дыма локально.
7. Разрешайте управляющие команды в параметрах интеграции только после проверки входа и устройства. Первое реальное включение выполняйте отдельно, рядом с подготовленной печью. В этой задаче оно не выполнялось.

## Повторный вход

Если Sangens отзовёт или просрочит сессию, HA создаст запрос повторной авторизации: можно снова войти по почте и коду. Администратор восстанавливает подключение один раз для всех. Токен другого контроллера не подменяет существующую привязку. Самостоятельного автоматического продления токена нет: соответствующий запрос в протоколе не подтверждён.

## Откат

Сохраните резервную копию до обновления. При проблемах восстановите прежний каталог компонента, перезапустите HA и верните сохранённую конфигурацию панели/ресурсов. Не восстанавливайте отдельные файлы `.storage` вручную во время работы HA; для записей настройки используйте штатное восстановление резервной копии. Печь при загрузке или откате не получает команд включения.

## Разработка и проверки

Используйте Python 3.14 и отдельное виртуальное окружение:

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements-test.txt
.venv/bin/python -m pytest -q
npm ci
npm test
```

Тесты HTTP-клиента поднимают локальный искусственный сервис. Запросы к настоящему аккаунту и печи в них не выполняются. Проверки hassfest и HACS запускаются отдельно в GitHub Actions; локальные тесты их не заменяют.
