# Установка и общая настройка

## Текущая готовность

Это предварительная реализация 0.1.0 для Home Assistant 2026.10.4 и Python 3.14. Автоматические проверки используют искусственные ответы. Совместимость действующего облачного аккаунта и выполнение команд настоящей печью не подтверждены.

В текущей сборке предусмотрен ввод легитимного токена доступа Sangens через интерфейс HA. Вход по почте и коду из письма ещё не поддерживается: не найден подтверждённый способ пройти штатную невидимую CAPTCHA с адреса HA. Пароля учётной записи в исследованном протоколе нет. Не извлекайте токены из приложения или браузера. До получения поддерживаемого входа или выданного производителем токена установка на действующий сервер в рамках этой задачи отложена.

Интеграция не делает фоновых попыток входа и не пытается обновлять CAPTCHA. При отказе авторизации она запрашивает повторный вход администратора. Опрос начинается раз в 30 секунд и замедляется при ошибках или ограничении частоты. Автоматического повтора команды нет. Это ограничивает лишние запросы, но не гарантирует отсутствие ограничений со стороны Sangens.

## Подготовка и установка после проверки входа

1. Создайте резервную копию HA. Сохраните существующий каталог `/config/custom_components/sangens`, если он есть, и конфигурацию панели. Старые записи `sangens_station` не удаляйте автоматически.
2. Распакуйте архив интеграции так, чтобы файлы оказались в `/config/custom_components/sangens/`. Не копируйте окружение разработки, APK, тесты или токены в общедоступный `/config/www/`.
3. Перезапустите HA в удобное время. Откройте «Настройки → Устройства и службы → Добавить интеграцию → Печь Sangens».
4. Администратор один раз вводит токен, полученный разрешённым способом, и выбирает печь. По умолчанию разрешено только чтение. Все пользователи HA получают те же сущности, повторно настраивать Sangens на телефонах не нужно.
5. Сравните температуру воздуха, камней, режим и состояние с официальным приложением. Несовпадение показаний не исправляется отправкой команд.
6. Подключите общий ресурс и карточку по `docs/card.md`. Сохраните настройки панели один раз для всех пользователей. При желании разместите личную копию дыма локально.
7. Разрешайте управляющие команды в параметрах интеграции только после проверки входа и устройства. Первое реальное включение выполняйте отдельно, рядом с подготовленной печью. В этой задаче оно не выполнялось.

## Повторный вход

Если Sangens отзовёт или просрочит токен, HA создаст запрос повторной авторизации. Администратор восстанавливает подключение один раз для всех. Токен другого контроллера не подменяет существующую привязку. Самостоятельного автоматического продления токена нет: соответствующий запрос в протоколе не подтверждён.

## Откат

Сохраните резервную копию до обновления. При проблемах восстановите прежний каталог компонента, перезапустите HA и верните сохранённую конфигурацию панели/ресурсов. Не восстанавливайте отдельные файлы `.storage` вручную во время работы HA; для записей настройки используйте штатное восстановление резервной копии. Печь при загрузке или откате не получает команд включения.

## Разработка и проверки

Используйте Python 3.14 и отдельное виртуальное окружение:

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements-test.txt
.venv/bin/python -m pytest -q
npm ci
npm test
```

Тесты HTTP-клиента поднимают локальный искусственный сервис. Запросы к настоящему аккаунту и печи в них не выполняются. Проверки hassfest и HACS запускаются отдельно в GitHub Actions; локальные тесты их не заменяют.
