# Простое управление Sangens в Home Assistant

Дата: 27 октября 2026. Статус: согласована пользователем; оригинальный дым подтверждён.

## Язык проекта

Документация, комментарии, сообщения коммитов, названия проверок и пользовательский интерфейс ведутся на русском языке. Стандартные программные интерфейсы HA, поля протокола Sangens и исходный текст лицензии сохраняются. Правило действует на дальнейшую реализацию.

## Результат

Одна карточка «Сауна» для телефона и компьютера: температура воздуха сейчас и заданная, температура камней, состояние печи, включение и выключение. Дополнительные настройки — внутри карточки. Подключение через облачный API Sangens, который использует исследованное Android-приложение.

Оборудование пользователя: Sangens W12G, 6 кВт, блок управления Sangens 6–9. Пользователь подтвердил доступность официального приложения. На предоставленном снимке воздух 28,7 °C, уставка 81 °C, камни 78 °C. Это снимок показаний, а не проверка текущего состояния или достоверности ответа API.

## Выбор подключения

Выбран облачный API: он соответствует существующему управлению через приложение и не требует добавления Bluetooth-оборудования на сервер. Зависит от интернета, сервиса Sangens и действующей авторизации.

Bluetooth остаётся отдельным возможным направлением. В приложении найдены UUID и команды, но их наличие не подтверждает совместимость конкретной прошивки, радиодоступность или безопасное воспроизведение полного управления. В первую версию Bluetooth не входит.

## Что известно из файлов

Исследованы предоставленная владельцем локальная заготовка и распакованный APK; исходные файлы не изменяются.

`custom_components/sangens` содержит только заготовку. Импортируется отсутствующий `utils`; папка называется `sangens`, а domain — `sangens_station`. Установленной рабочей интеграцией эти локальные файлы не являются. Имеющиеся незакоммиченные изменения пользователя сохраняются. В GitHub-репозитории домен уже исправлен на `sangens`, но setup пока создаёт только тестовое состояние `sangens_station.world`. Реализация начинается с этой версии GitHub в отдельной ветке.

APK содержит React Native/Hermes bundle. Декомпилированный файл `apk/SANGENS/hermes-dec/tmp/my_output_file.js` — источник для восстановления протокола, а не готовый поддерживаемый исходный проект. Некоторые фрагменты уже отредактированы и снабжены комментариями; критические значения при необходимости сверяются с `.hasm` и оригинальным bundle.

Обнаруженный адрес: `https://api.sangens.com/api`. Подтверждения актуальности протокола на авторизованном устройстве пока нет.

| Назначение | Обнаруженный запрос | Поле |
| --- | --- | --- |
| Список устройств | GET `/microchip-user` | — |
| Устройство | GET `/microchip-user/{id}` | — |
| Вкл./выкл. | POST `/microchips/{microchip_id}/set-remote-control-status` | `remoteControlStatus`: `ON` / `off` |
| Температура воздуха | POST `/microchips/{microchip_id}/set-air-temperature` | `setAirTemperature` |
| Температура камней | POST `/microchips/{microchip_id}/set-target-stone-temperature` | `targetStoneTemperature` |
| Режим | POST `/microchip-user/{id}/set-mode` | `modeId` |

Идентификатор привязки пользователя и идентификатор контроллера различаются. Нельзя подставлять серийный номер вместо них.

Найденные поля состояния: `microchip.connectionStatus`, `microchip.data.remoteControlStatus`, `currentAirTemperature`, `setAirTemperature`, `firstStoneTemperature`, `secondStoneTemperature`, `targetStoneTemperature`, признаки работы нагревателей. Приложение сравнивает `remoteControlStatus` с `ON` для определения включения. Сам факт включения не означает активный нагрев.

Опорные участки декомпиляции: настройка API около строки 370619; Bearer-заголовок 380410; авторизация 456235–456282; состояния и режимы 588135–588200; поля телеметрии 589520–589620; запросы устройства 592790–593070; проверка включения 784690–784720.

## Авторизация и первая проверка

Найден вход через email: `/email/send`, `/email/check`, `/auth/loginByEmail`, затем Bearer-токен. DTO отправки почты содержит `recaptcha`. Нельзя считать, что PIN блока управления позволяет авторизоваться в облаке, или заменять эту схему обычным паролем.

Первый этап реализации — проверить разрешённый пользовательский вход и чтение списка устройств. Пользователь вводит почту и одноразовый код через локальный интерфейс настройки; CAPTCHA, если обязательна, проходит сам в штатном интерфейсе Sangens. CAPTCHA не обходится. До подтверждения пригодного для HA способа авторизации не обещается полностью автоматическая первоначальная настройка.

Если действующий API требует шаг, который нельзя корректно выполнить в интерфейсе настройки HA, сначала фиксируется конкретное ограничение и выбирается доступный способ авторизации с пользователем. Извлечение токенов из памяти приложения или браузера не является предусмотренным способом входа. Не создаются фиктивные кнопки подключения, скрывающие это ограничение.

Токен сохраняется только на сервере HA в настройках интеграции, не в карточке, коде, диагностике или отчёте. При отказе авторизации интеграция просит повторный вход. Обновление токена не выдумывается: соответствующий механизм Sangens пока не подтверждён.

### Одна настройка для всех пользователей

Администратор один раз добавляет интеграцию и выбирает печь. Вход в Sangens, привязка контроллера и параметры подключения хранятся в одной серверной записи HA. Все пользователи и телефоны работают с одними сущностями и одной общей панелью; отдельные аккаунты Sangens, ввод PIN или настройка каждой карточки на каждом устройстве не нужны.

Браузеры и Companion обращаются только к HA. Токен Sangens не передаётся клиентам; сервер HA выполняет команды от имени общего подключения. Права пользователей определяются возможностями HA; карточка не является средством разграничения доступа. Настройка и повторная авторизация доступны администратору. После перезапуска HA и открытия с другого телефона подключение восстанавливается из серверных настроек без повторного ввода. Если Sangens отзовёт или просрочит токен, администратор один раз восстанавливает вход для всех.

## Устройство интеграции

Единый домен и каталог `sangens`, настройка через интерфейс HA. Перед развёртыванием проверяется, нет ли на сервере старых записей `sangens` или `sangens_station`; они не удаляются автоматически.

Отдельный асинхронный клиент отвечает за HTTP, проверку ответов и исключения. Координатор получает состояние и раздаёт его сущностям. Сущности HA не дублируют HTTP-запросы. Используется общий HTTP-клиент HA и проверка TLS.

Основные сущности:

- `climate`: температура воздуха, уставка, режимы HA «выключено» и «нагрев».
- Датчик температуры камней; второй датчик только если он существует в ответе конкретного устройства.
- `number`: уставка камней, если API сообщает допустимые границы.
- `select`: существующие режимы устройства, полученные из его данных. Создание режимов не входит в версию 1.
- Доступность и время последнего успешного чтения для диагностики.

Границы температур определяются данными режима/устройства и проверяются до отправки. Диапазон дуги на скриншоте не принимается за разрешённый диапазон команд. Неизвестные состояния и отсутствующие значения не заменяются нулём или состоянием «выключено».

Опрос в первой версии — каждые 30 секунд без параллельных запросов к одному устройству; при ограничениях API или ошибках применяется увеличение интервала. После команды выполняется обновление состояния. Неподтверждённое изменение не отображается как выполненное.

## Карточка

Локальная адаптивная карточка, поставляемая вместе с интеграцией: крупная текущая температура, уставка и статус; рядом температура камней. Дополнительные параметры открываются через карточку устройства. Локальный ресурс карточки подключается администратором один раз и используется общей панелью. Никаких настроек подключения или токенов внутри клиентского кода. Стандартная карточка HA остаётся запасным способом управления теми же сущностями.

### Дым и оформление из приложения

По запросу пользователя использовать подходящие оригинальные ресурсы из предоставленного APK в его домашней панели. Найдены `res/raw/src_assets_videos_background.mp4` (около 936 КиБ), `src_assets_videos_intro.mp4` и изображения. Пользователь подтвердил, что фоновое видео соответствует желаемому дыму. Оригинальные медиа хранятся локально для домашней установки и не коммитятся в публичный репозиторий; карточка использует локальный URL, который администратор задаёт один раз. `active_regime_background.png` проверен: это однотонная подложка с округлением, а не изображение дыма.

Дым показывается как декоративный фон состояния работающей печи и не перекрывает цифры или кнопки. Состояние «Нагревает» появляется только при соответствующей телеметрии; наличие анимации само по себе не означает активные нагреватели. При выключении, потере связи и необходимости входа дым не воспроизводится. Неизвестное состояние не оформляется как работающее устройство.

Видео локальное, без звука, с `playsinline`; повторяется только пока карточка видима и данные подтверждают включение. При скрытии страницы или карточки воспроизведение останавливается. Для уменьшения движения, отказа автопроигрывания и экономии ресурсов предусмотрена статичная подложка. Текст и значки сохраняют достаточную читаемость поверх дыма на телефоне и компьютере. Ресурсы приложения не объявляются собственными и не включаются в публичный выпуск без проверки условий их распространения.

Явная кнопка «Включить» запрашивает подтверждение. «Выключить» отправляет выключение без дополнительного диалога. Не используется одна команда toggle. Подтверждение относится к карточке; прямые команды HA доступны авторизованным пользователям HA.

Состояния: «Выключена», «Включена», «Нагревает» только при подтверждённом признаке нагревателей, «Нет связи», «Нужен вход». Цвет не является единственным указателем состояния.

## Команды и сбои

Нет отправки включения при загрузке HA, восстановлении сети или настройке интеграции. Изменение уставки или режима не должно запускать печь. До проверки этой особенности API изменение режима/уставки при выключенной печи блокируется; если API совмещает настройку с запуском, такие действия требуют того же явного подтверждения, что и включение.

Команды не сохраняются в очередь и не повторяются автоматически после тайм-аута: результат может быть неизвестен. После неоднозначного ответа обновляется состояние и показывается понятная ошибка. При неподтверждённой связи, некорректных данных или незавершённой предыдущей команде запуск не отправляется. Отключённые контроллером разрешения удалённого управления не обходятся.

Интеграция не заменяет штатные защиты, ограничения времени и управление самого контроллера. Расписания, отложенный старт и автозапуск в первую версию не входят.

## Проверка и установка

1. Проверить авторизацию и чтение данных без управляющих запросов; сверить показания с приложением.
2. Покрыть тестами разные идентификаторы устройства/контроллера, регистр `ON`/`off`, вложенность ответов, ограничения температур, неизвестные значения, отказ авторизации, отсутствие сети, тайм-аут команды и отсутствие автозапуска/повторов. Для тестов использовать обезличенные ответы и имитацию HTTP.
3. Проверить загрузку на установленной версии HA и совместимость сущностей. Проверить карточку на узком и широком экране, остановку анимации, статичный вариант и читаемость цифр. Открыть общую панель под вторым пользователем и на другом устройстве: дополнительный вход в Sangens не требуется, токена в загружаемых ресурсах и сетевых запросах клиента нет.
4. Сделать резервную копию затрагиваемых серверных файлов и панели, установить только компонент и карточку. Не менять маршрутизацию, другие интеграции или конфигурацию Docker ради Sangens.
5. Проверка настоящего включения — отдельный контролируемый шаг с пользователем рядом с подготовленной печью. До него управление проверяется на имитации API. Установка и чтение показаний сами по себе не подтверждают реальное выполнение команд.

Готовность: первоначальный вход пройден, данные совпадают с приложением, карточка работает на телефоне, сбои дают понятное состояние, тесты поведения пройдены, резервная копия и способ отката описаны. Непроверенные на устройстве команды явно отмечаются в отчёте.
